# SUBLEVEL Unsigned — moderated beta

Separate service, separate accounts, PostgreSQL data shared between devices. No changes to the main magazine or its local accounts. No uploaded audio files; link only. All submissions and feedback require moderator approval. Votes use one row per track and member. Own-track votes are rejected. Producer rankings require five approved ratings, with Bayesian-style neutral prior (five ratings at 10). No fabricated content. Account deletion cascades. Password hashes use Werkzeug scrypt; CSRF on POST, HTTP-only secure cookies, rate budgets in PostgreSQL, validated link hosts and escaped templates.

## Beta limitations
Invite-only. No email verification, password reset, robust anti-Sybil identity verification, legal/privacy review, independent security audit or production load test. Rank weighting is not fraud-proof. Public bios require human oversight. Database expiry requires export/migration before 30 days. Free web service may sleep and monthly workspace usage limits apply. Not a production launch. Do not reuse main magazine credentials.

## Member controls and launch information
Public /community-guide describes the invite-only pilot, community standards, public fields, cookies, third-party playback, withdrawals, deletion and database limitations. It is not a legally reviewed privacy notice or terms of service. Members can hide their own submissions from discovery/rankings and remove their own ratings/reviews; external source files are untouched. Withdrawal retains the submission privately for the owner/moderator. No permanent public launch until controller/contact details, data retention and backup plan, legal review, and durable database are agreed. Do not publish credentials or open database network access.

Account settings now offer password rotation (current password and confirmation required), invalidation of previous signed sessions using an additive session_version database field, and password-confirmed member-only JSON data export. The migration intentionally signs out previously issued cookies lacking a version; members sign in again with their existing passwords. Export includes own profile, submissions, feedback and reports, not authentication secrets or other members' private data. It is a member export, not a full database backup. Forgotten-password recovery remains unimplemented.

## One-time recovery
Members can generate a 256-bit one-time recovery code in Account settings after password confirmation. Only its SHA-256 digest is stored. The code is shown in a no-store POST response, not cookies, URL parameters, exports or logs. Generating another code, ordinary password changes and successful recovery invalidate the previous code. Reset uses a conditional database update to prevent replay, invalidates previous sessions and requires a new sign-in. No email or third-party recovery service; members must save a code in advance, and loss of both password and code remains unrecoverable. The code is equivalent to a sensitive credential; never share it. This is not a substitute for independent security review.
